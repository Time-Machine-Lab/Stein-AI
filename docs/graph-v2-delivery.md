# Graph V2 使用与发布说明

本文对应 `codex/graph-production` 的实现。发布、设备和真实模型验收结果以文末证据表为准；本地测试通过不代表已经部署。

## 功能范围

| 能力 | 行为和边界 |
| --- | --- |
| AI 编排 | 从自然语言创建流程：选择参与智能体、一个默认执行者和审批人后进入**多轮对话**，左边聊、右边实时画布，每条回复即合并进草稿并可撤销、可刷新续聊；服务端不再需要模型密钥，对话也没有次数上限。没有创作会话能力的部署仍保留旧的一次性表单（提案 → 应用/丢弃）。 |
| 可视化编辑 | 编辑节点与连线、分支端口、输入映射、输出结构；支持嵌套流程、撤销和草稿恢复。步骤名称与稳定标识分离。 |
| 分支与并行 | 条件支持类型校验；未选择的路径标记跳过；汇合等待所有输入路径有明确结果。并发上限作用于整个运行，包括子流程。 |
| 有界循环 | 至少执行一轮，完成后判断是否继续；每轮有独立输入、执行实例和记录。达到上限仍需继续时明确失败。 |
| 扩展节点 | 人工审批、延迟、HTTP、JavaScript/Python 脚本和嵌入式子流程。脚本使用所选已有运行时，不在后端服务进程中执行。 |
| 人工审批 | 支持全员、任一人、指定票数；票据绑定不可变候选证据。换人后生成新票据，旧票不计入新审批。 |
| 自动触发 | 定时、Webhook、任务事件；持久化事件、去重键和执行租约。重启后定时器补一个错过的时点，避免集中重放大量模型任务。 |
| 运行与恢复 | 输入结构校验、仓库和提交选择、运行时绑定、暂停/继续/取消、失败重试和关联返工运行。 |
| 观察 | 列表搜索、状态过滤、游标分页、耗时/用量统计、实时刷新、节点日志、结果、审批证据及产物。未定价用量明确列为未定价。 |
| 执行器 | 复用项目已有运行时、任务队列、租约、Skills、插件与 Remote MCP。各原生适配器的认证及版本要求见运行时兼容矩阵。 |

V1 已发布版本继续按原串行语义运行，新的 V2 发布不会改写历史版本或运行快照。

本次范围不包含多仓库交付、并行代码产物自动合并、检查点分叉、自动合并 PR/部署和外部系统补偿事务。并行分支产出不可比较的代码提交时，后续代码节点会明确阻塞；不会自行猜测应该合并哪一个提交。

## 使用流程

1. 在工作区运行时页面确认所需原生 CLI 在线，创建或选择智能体，配置明确模型。Graph 使用这些已有资源。
2. 打开 Graph，选择 AI 创建或手动创建。AI 创建分两步：先选**参与的智能体**、其中一个**默认执行者**与审批人；然后进入对话，描述目标、判断条件和验收方式，需要改动就直接说。对话跑在默认执行者的运行时上，因此该智能体需要在线；每条回复里的草稿会立刻合并到右侧画布，可以撤销，也可以随时停止或退出。
3. 在画布中调整步骤、分支、并行或循环，选择步骤配置输入来源及输出结构。引用分支可能跳过的输出时设置默认值或允许缺失。
4. 保存草稿并发布。发布固定节点定义、智能体配置、模型、Skills 和插件引用；凭据在执行时按已授权引用解析。
5. 启动时选择根任务、运行时与输入。如果需要代码交付，选择仓库和具体提交作为起点。
6. 在运行页查看各实例的状态及结果。人工审批针对页面显示的候选证据投票；需要重新执行整个流程时使用关联返工运行。
7. 如需自动启动，在 Graph 详情配置触发器。Webhook 密钥只在生成时展示，丢失后轮换；投递记录显示实际启动或拒绝原因。

AI 创建与节点执行是两条接入路径：**AI 编排不再使用服务端模型**。创作对话是一条普通的聊天空会话（隐藏的载体智能体 + `chat_session`），因此消息、流式、停止、归档和实时刷新都走现有 chat 通路；草稿由回复里的 `<graph_draft>` 块给出，前端解析后合并，服务端不存草稿。对话可以覆盖多个参与智能体，草稿里不同步骤可以分给范围内的不同智能体。节点执行同样使用用户选择的现有运行时与模型。

`MULTICA_LLM_API_KEY`、`MULTICA_LLM_BASE_URL` 和 `MULTICA_LLM_DEFAULT_MODEL` 现在只服务 chat 自动标题与 chat 快捷操作，与 Graph 无关；未配置它们不影响 AI 编排。AI 编排的失败形态改为：智能体不可用或运行时离线（进入对话前就拦住并给出原因）、对话里模型没给出可用的草稿块（画布保持上一版并说明原因，对话可继续）、以及服务端侧的改写让草稿失效。最后的**保存、校验、发布**仍是人工步骤，创作过程不会自动保存或运行。

## 执行和失败语义

- 任务提交的结果先暂存，只有进程停止证据、结果结构和交付检查都通过后才会被接受。取消或失败会等待活动进程停止，无法证明停止时保持可见阻塞。
- HTTP 只允许受限制的 HTTP(S) 目的地址，拒绝本机/内网等受保护目标与重定向，限制请求头、响应大小和时间。外部状态码作为节点输出交给分支处理。
- HTTP 使用稳定 `Idempotency-Key`。GET/HEAD 最多尝试三次；修改远端状态的请求若结果不明，需要明确理由才能重试。远端服务未实现幂等时，人工重试仍可能重复操作。
- 草稿、运行、审批和触发器控制带版本或幂等约束，过期界面的操作会被拒绝并要求刷新。
- 运行定义最多四层子流程、每层 128 节点/256 连线、按循环上界最多 4,096 个执行实例；单次循环最多 100 轮。完整定义上限 256 KiB，运行文档上限 16 MiB，其中为停止与终态保留 1 MiB。
- 统计中的模型费用沿用现有用量定价，缺少价格的任务不按零费用解释。

## 数据库与部署

数据库需要升级到 `375_drop_graph_generation`（该迁移删除已下线的一次性 AI 生成队列表 `graph_generation`；更早的 372–374 仍留在树里，因为迁移只追加不重写）。后端部署使用现有迁移入口，自动执行尚未应用的迁移；无需逐个手工运行 SQL。所有 Graph 并发索引均登记了失效索引清理钩子，中断后重试不会将不可用索引当作成功。

正常顺序：通过 CI → 发布服务端与前端 → 确认迁移和就绪检查成功 → 更新执行 Graph 的 daemon → 验收后开放触发器。旧 daemon 不能证明 V2 能力时会被阻止领取相应 Graph 任务，普通任务仍使用原有路径。

自托管 Compose 已传递两项 Graph 运行控制（`MULTICA_LLM_*` 仍是可选项，只影响 chat，与 Graph 无关）：

| 环境变量 | 设置为 `true` 后 |
| --- | --- |
| `MULTICA_GRAPH_DISABLE_NEW_RUNS` | 拒绝新 Graph 运行，暂停触发器派发；已入队事件保留。 |
| `MULTICA_GRAPH_DISABLE_ADVANCEMENT` | 停止派发后续节点，同时保留回执处理和取消恢复。 |

两项默认均为 `false`，不改变普通任务、聊天和自动化流程。Compose 修改环境变量后需要重建后端容器才能生效。

紧急处理先关闭新运行和推进，再取消或排空正在执行的 Graph。优先保留新增数据库结构并修复应用；不要把旧版 coordinator 直接放回仍有 V2 活跃运行的数据库。数据库降级会删除触发器数据，并尝试恢复 V1 的每运行单个待审批约束；存在多门待审批或仍有 V2 活动运行时不可执行。迁移 CLI 的 `down` 会回退其找到的所有已应用迁移，不能直接用于生产的局部回滚。

本机限定工作区的验收示例：

```powershell
multica daemon start --workspace-id 06c89e9a-f311-4324-b5d9-9acd3114228b --no-auto-update --no-auto-reload
```

也可使用 `MULTICA_DAEMON_WORKSPACE_IDS` 设置工作区 UUID 白名单。不显式指定时保留原有发现全部可访问工作区的行为。
