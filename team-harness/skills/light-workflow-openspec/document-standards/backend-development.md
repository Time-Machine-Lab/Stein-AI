# Backend Development Spec 文档规范

Backend Engineer 使用本模板说明当前项目的后端如何组织和开发。文档不是 Backend 教程，也不描述 Workflow 协作职责。

## 必须说明

- Backend 使用的技术栈和版本约束；
- 后端工程的目录结构；
- 每个目录和关键文件的职责；
- 服务、领域、数据和 API 的边界；
- 模块之间的依赖和协作方式；
- 数据模型、迁移和持久化约束；
- API 契约、错误处理、权限和兼容性要求；
- 项目特有的开发约束和实现边界。

工程目录必须使用文件树展示，并在节点旁说明目录或关键文件的职责，例如：`src/`（服务和领域代码）。

## 合格标准

文档能够让新的 Backend Engineer 明确本项目使用什么技术栈、代码应该放在哪里、各部分负责什么，以及模块如何协作。

技术栈没有被 Product Concept 或项目已有约束指定时，选择简单、成熟、适合当前目标的方案。产品形态或技术栈未确认时，不进入工程初始化。
