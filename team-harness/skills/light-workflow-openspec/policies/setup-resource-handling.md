# Setup Resource Handling

## 发现资源缺失

使用某项资源的 Role 负责报告：

- 缺少什么资源；
- 哪一步因此无法继续；
- 需要用户提供、授权还是做产品决定；
- 是否存在不改变范围的替代方案。

Delivery Manager 负责协调和向用户确认，不代替专业 Role 判断资源是否满足其领域要求。

Setup 时由 Delivery Manager 在当前运行时创建项目根目录同级的 `TML-Secret/`，并创建 `<项目名>.env`。项目名取当前项目根目录名称，不取本 Skill 所在目录名称。

## 非敏感资源

项目资产、设计素材、测试数据说明和外部服务说明统一放在：

```text
tml-docs/assets/
```

文档中同时说明资源的用途、所有者、使用环境和更新方式。

## 敏感凭据

API Key、密码、Token、私密账号和其他敏感值不得写入 `tml-docs/`，不得提交到仓库。

为了让团队 Agent 共享使用，敏感值统一写入该运行时文件。Agent 在执行任务前从该文件读取所需变量并注入运行环境，不得在 Issue、日志、文档或聊天中输出敏感值。该目录不属于项目仓库，不得复制到项目内。

在 `tml-docs/secret-requirements.md` 中只记录：

- 所需的环境变量名称；
- 凭据由谁提供；
- 哪个环境需要它；
- 如何验证已经配置成功；
- `TML-Secret/<项目名>.env` 中的变量名和位置。

缺少敏感凭据且无法继续时，暂停并通知 Delivery Manager。不得猜测、伪造或把示例值当作真实凭据。
